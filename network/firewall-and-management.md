# Firewall and Management

[Home network index](README.md)

## Router Firewall Policy

### Input Chain

Current high-level order:

```text
accept established,related,untracked
drop invalid

allow IoT NTP
allow IoT DNS TCP
allow IoT DNS UDP
allow IoT DHCP

allow ICMP
allow loopback/CAPsMAN

drop everything not coming from LAN
```

Because `vlan20-iot` is not in the `LAN` interface list, IoT devices cannot access general router-management services.

### Forward Chain

Current high-level order:

```text
accept IPsec-in policy
accept IPsec-out policy

fasttrack established/related
accept established/related/untracked
drop invalid

drop new traffic from WAN not DSTNATed

allow Home Assistant -> IoT
allow test phone -> Internet
allow existing IoT device -> Internet
allow vacuum -> Internet

drop all other routed traffic entering from vlan20-iot
```

Current IoT Internet exceptions:

```text
192.168.20.100  test phone
192.168.20.101  existing IoT device
192.168.20.102  vacuum
```

The temporary "allow all IoT Internet" rule is no longer present.

There is currently no explicit trusted-LAN -> IoT drop, so `192.168.88.0/24 -> 192.168.20.0/24` is currently allowed unless another rule blocks it. This is intentional for now.

### IoT Peer Isolation

CAPsMAN has:

```text
client-to-client-forwarding=no
```

for the IoT datapath.

This prevents direct client-to-client forwarding on the same CAP interface, but does not necessarily guarantee full Layer-2 isolation between IoT clients associated with different APs.

Full peer-isolation testing is deferred.

## Router Management Hardening

### hAP ac3

Enabled:

```text
SSH    TCP/22
WinBox TCP/8291
```

Restricted to:

```text
192.168.88.0/24
```

Disabled:

```text
FTP
Telnet
HTTP WebFig
HTTPS WebFig
reverse-proxy
API
API-SSL
```

MAC-based management is disabled:

```text
MAC server:         none
MAC WinBox:         none
neighbor discovery: none
```

### wAP ac

The same management-hardening model is applied:

- SSH from trusted LAN only
- WinBox from trusted LAN only
- HTTP/API/etc. disabled
- MAC server disabled
- MAC WinBox disabled
- neighbor discovery disabled

### WebFig Status

WebFig is currently disabled.

Planned approach:

```text
HTTPS only
Trusted LAN only
No plaintext HTTP
```

Certificate strategy is still to be decided.

## IPv6 / Thread

The hAP currently has no general global IPv6 Internet route/prefix configured.

Observed IPv6 behavior includes local Router Advertisements generated by the Apple TV for Thread-related routing.

Before bridge VLAN filtering was enabled, Apple TV IPv6 Neighbor Discovery traffic leaked onto IoT wireless interfaces. After enabling proper bridge VLAN filtering on the hAP and wAP, this leakage stopped.

Thread functionality on the trusted LAN should therefore be preserved without leaking trusted-LAN Layer-2 multicast into the IoT WLAN.
